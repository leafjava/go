# 6. 监听事件 — 步骤解析

本文档梳理了通过 Go 订阅以太坊智能合约事件日志（以监听 USDT Transfer 事件为例）的完整流程。

---

## 整体概览

```
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 1. 连接节点  │ → │ 2. 准备地址   │ → │ 3. 创建过滤器 │ → │ 4. 订阅日志   │
│  wss:// 必须  │    │  USDT 合约    │    │ FilterQuery   │    │ Subscribe...  │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
                                                                    │
                                                                    ▼
┌──────────────┐    ┌──────────────┐    ┌──────────────┐    ┌──────────────┐
│ 7. 格式化输出│ ← │ 6. 接收日志   │ ← │ 5. 错误监听   │ ← │  返回 sub    │
│ BlockNumber  │    │  <-logs chan │    │  <-sub.Err() │    │  + chan       │
└──────────────┘    └──────────────┘    └──────────────┘    └──────────────┘
```

---

## 步骤 1：连接以太坊节点（必须用 WebSocket）

```go
client, err := ethclient.Dial("wss://eth.llamarpc.com")
if err != nil {
    log.Fatal(err)
}
defer client.Close()
```

| 项目 | 说明 |
|------|------|
| **协议** | **必须使用 `wss://`**（WebSocket Secure），不能用 `https://` |
| **原因** | `SubscribeFilterLogs` 需要持久长连接来实时推送日志，HTTP 是一次性请求-响应，不支持订阅 |
| **常见端点** | `wss://ethereum.publicnode.com`、`wss://eth.llamarpc.com` 等 |

> ⚠️ **关键区别**：`CallContract`（part5 查询余额）用 HTTP 即可，`SubscribeFilterLogs`（订阅事件）必须用 WebSocket。

---

## 步骤 2：准备合约地址

```go
contractAddress := common.HexToAddress("0xdAC17F958D2ee523a2206206994597C13D831ec7")
```

| 项目 | 说明 |
|------|------|
| **contractAddress** | USDT 以太坊主网合约地址 |
| **作用** | 告诉过滤器只监听这个合约产生的事件日志 |

---

## 步骤 3：创建过滤器

```go
query := ethereum.FilterQuery{
    Addresses: []common.Address{contractAddress},
}
```

| 字段 | 说明 |
|------|------|
| **Addresses** | 要监听的合约地址列表，可以同时监听多个合约 |
| **Topics** | （未设置）事件主题过滤器，这里不填表示接收所有事件 |
| **FromBlock / ToBlock** | （未设置）区块范围，订阅模式下通常不填，表示从最新区块开始实时监听 |

> `FilterQuery` 结构体支持的字段：
>
> ```go
> type FilterQuery struct {
>     BlockHash *common.Hash     // 指定单个区块（与 FromBlock/ToBlock 互斥）
>     FromBlock *big.Int         // 起始区块
>     ToBlock   *big.Int         // 结束区块
>     Addresses []common.Address // 合约地址列表
>     Topics    [][]common.Hash  // 事件主题过滤
> }
> ```

---

## 步骤 4：订阅日志

```go
logs := make(chan types.Log)
sub, err := client.SubscribeFilterLogs(context.Background(), query, logs)
if err != nil {
    log.Fatal(err)
}
```

| 项目 | 说明 |
|------|------|
| **logs** | Go channel，类型为 `chan types.Log`，有新日志时自动推送 |
| **sub** | 订阅对象，提供 `Err()` 方法返回订阅错误通道 |
| **SubscribeFilterLogs** | 发起 `eth_subscribe` RPC 请求，建立 WebSocket 推送通道 |
| **context.Background()** | 上下文控制，可设置超时来限制订阅时长 |

> 内部机制：客户端向节点发送 `eth_subscribe("logs", {address: [...]})`请求，节点确认后每当新区块中包含匹配的日志时，就会主动推送到客户端。

---

## 步骤 5 & 6：循环监听（select 多路复用）

```go
for {
    select {
    case err := <-sub.Err():
        log.Fatal(err)
    case vLog := <-logs:
        fmt.Printf("区块: %d, 交易: %s\n", vLog.BlockNumber, vLog.TxHash.Hex())
    }
}
```

| 通道 | 说明 |
|------|------|
| **sub.Err()** | 订阅错误通道，连接断开、超时等异常时会收到错误。收到后程序直接退出 |
| **logs** | 日志数据通道，每匹配到一条链上日志就收到一个 `types.Log` 结构体 |

### `types.Log` 结构体

```go
type Log struct {
    Address     common.Address // 产生日志的合约地址
    Topics      []common.Hash  // 事件签名 + 索引参数（最多 4 个）
    Data        []byte         // 非索引参数的 ABI 编码数据
    BlockNumber uint64         // 所在区块号
    TxHash      common.Hash    // 所在交易哈希
    TxIndex     uint           // 交易在区块中的索引
    BlockHash   common.Hash    // 区块哈希
    Index       uint           // 日志在交易中的索引
    Removed     bool           // 是否因链重组被移除
}
```

## 完整代码

```go
package main

import (
    "context"
    "fmt"
    "log"

    "github.com/ethereum/go-ethereum"
    "github.com/ethereum/go-ethereum/common"
    "github.com/ethereum/go-ethereum/core/types"
    "github.com/ethereum/go-ethereum/ethclient"
)

func main() {
    // 1. WebSocket 连接（必须）
    client, err := ethclient.Dial("wss://eth.llamarpc.com")
    if err != nil {
        log.Fatal(err)
    }
    defer client.Close()

    // 2. 合约地址
    contractAddress := common.HexToAddress("0xdAC17F958D2ee523a2206206994597C13D831ec7")

    // 3. 创建过滤器
    query := ethereum.FilterQuery{
        Addresses: []common.Address{contractAddress},
    }

    // 4. 订阅日志
    logs := make(chan types.Log)
    sub, err := client.SubscribeFilterLogs(context.Background(), query, logs)
    if err != nil {
        log.Fatal(err)
    }

    fmt.Println("开始监听事件...")

    // 5-7. 循环监听 + 错误处理 + 输出
    for {
        select {
        case err := <-sub.Err():
            log.Fatal(err)
        case vLog := <-logs:
            fmt.Printf("区块: %d, 交易: %s\n", vLog.BlockNumber, vLog.TxHash.Hex())
        }
    }
}
```

## 关键概念

| 概念 | 解释 |
|------|------|
| **事件（Event）** | 智能合约中的 `emit` 语句产生的日志，永久存储在链上 |
| **日志（Log）** | 事件的链上存储形式，包含地址、Topics（主题）、Data（数据） |
| **Topic** | 索引字段，事件签名 Keccak-256 哈希放在 Topics[0]，indexed 参数放在后续位置 |
| **FilterQuery** | 过滤器配置，可按合约地址、事件主题、区块范围筛选日志 |
| **eth_subscribe** | JSON-RPC 推送机制，节点主动推送新日志给客户端 |
| **WebSocket vs HTTP** | 查询用 HTTP 即可；订阅/推送必须用 WebSocket 长连接 |

## WebSocket 订阅 vs HTTP 查询 对比

| 特性 | SubscribeFilterLogs (wss) | FilterLogs (http) |
|------|--------------------------|-------------------|
| 连接方式 | WebSocket 长连接 | HTTP 短连接 |
| 数据获取 | 节点主动推送 | 客户端主动请求 |
| 实时性 | 实时 | 需轮询 |
| 历史数据 | 仅之后新产生的 | 任意区块范围 |
| 适用场景 | 实时监控、监听 | 回溯查询、一次性获取 |
