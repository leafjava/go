# 二层网络（Layer 2 / L2）详解

## 一、为什么需要 L2

### 1.1 L1 的困境

以太坊主网（L1）面临不可能三角中的性能瓶颈：

```
以太坊 L1 现状（2026）：
  TPS:        ~15-30 笔/秒
  区块 Gas:   ~30M（目标）
  简单转账:   21000 Gas → ~$1-3
  Uniswap 交易: ~150000 Gas → ~$10-30
  区块间隔:   ~12 秒
  最终确定:   ~12.8 分钟（2 Epoch）
```

对于交易所和 DeFi 场景，这个吞吐量和成本是完全不可接受的。用户提 100 USDT 花 20 刀 Gas 是常态。

### 1.2 L2 的核心思路

```
                     ┌────────── L1 以太坊 ──────────┐
                     │  只做结算 + 数据可用性           │
                     │  • 存储压缩后的交易数据          │
                     │  • 验证 L2 提交的证明            │
                     │  • 处理 L2→L1 的提款             │
                     └──────────┬─────────────────────┘
                                │
              ┌─────────────────┼─────────────────┐
              │                 │                 │
     ┌────────▼──────┐ ┌───────▼───────┐ ┌───────▼──────┐
     │ Optimistic    │ │  ZK Rollup   │ │  Validium    │
     │ Rollup        │ │              │ │              │
     │ 欺诈证明      │ │ 有效性证明    │ │ 链下数据     │
     └───────────────┘ └──────────────┘ └──────────────┘
```

**一句话**：把交易执行搬到链下（L2），只把压缩后的证明或状态根提交到 L1 做结算。

## 二、四大技术路线

### 2.1 Optimistic Rollup（乐观汇总）

**核心思想**：默认所有交易都有效，留挑战期（7 天）让人举报欺诈。

```
流程：

  Sequencer 打包交易
       ↓
  生成 L2 区块 + 状态根
       ↓
  提交压缩数据到 L1 （calldata/blob）
       ↓
  ┌──────── 7 天挑战期 ────────┐
  │  有人提交欺诈证明？          │
  │  ├─ 是 → 回滚该批次         │
  │  └─ 否 → 状态根最终确认     │
  └───────────────────────────┘
```

#### Go 代码示例：Optimistic Rollup 核心逻辑

```go
package optimistic

import (
    "crypto/sha256"
    "fmt"
    "time"
)

// ─── Optimistic Rollup 核心组件 ───

// L2Batch L2 批次
type L2Batch struct {
    BatchID      uint64
    Transactions []string       // 原始交易数据
    PrevStateRoot [32]byte      // 上一状态根
    NewStateRoot  [32]byte      // 执行后新状态根
    DataHash      [32]byte      // calldata 哈希
    SubmittedAt   time.Time     // 提交到 L1 的时间
    ChallengeWindow time.Duration // 挑战窗口（7天）
}

// L1Contract L1 上的 Rollup 合约（简化版）
type L1Contract struct {
    Batches      map[uint64]*L2Batch
    FinalizedBatches map[uint64]bool // 已最终确定的批次
    ChallengeWindow  time.Duration
}

// SubmitBatch Sequencer 提交批次到 L1
func (c *L1Contract) SubmitBatch(batch *L2Batch) error {
    // 1. 验证 prevStateRoot 匹配
    // 2. 存储批次数据（calldata/blob）
    // 3. 开始挑战窗口倒计时

    c.Batches[batch.BatchID] = batch
    batch.ChallengeWindow = 7 * 24 * time.Hour // 7 天
    batch.SubmittedAt = time.Now()

    fmt.Printf("[OR] 批次 %d 已提交 L1 | 交易数: %d | 状态根: 0x%x | 挑战窗口: 7天\n",
        batch.BatchID, len(batch.Transactions), batch.NewStateRoot[:8])
    return nil
}

// ChallengeBatch 任何人都可以提交欺诈证明挑战某个批次
func (c *L1Contract) ChallengeBatch(
    batchID uint64,
    fraudProof *FraudProof,
    challenger string,
) error {
    batch, ok := c.Batches[batchID]
    if !ok {
        return fmt.Errorf("批次 %d 不存在", batchID)
    }

    // 1. 检查是否在挑战窗口内
    if time.Since(batch.SubmittedAt) > batch.ChallengeWindow {
        return fmt.Errorf("挑战窗口已关闭")
    }

    // 2. 检查是否已被挑战
    if _, finalized := c.FinalizedBatches[batchID]; finalized {
        return fmt.Errorf("批次已最终确定")
    }

    // 3. 验证欺诈证明
    if !c.verifyFraudProof(batch, fraudProof) {
        return fmt.Errorf("欺诈证明验证失败")
    }

    // 4. 欺诈证明有效 → 回滚批次
    fmt.Printf("[OR] ⚠️ 欺诈证明有效！回滚批次 %d\n", batchID)
    fmt.Printf("[OR]    挑战者 %s 获得奖励\n", challenger[:16]+"...")
    fmt.Printf("[OR]    Sequencer 被罚没保证金\n")

    // 回滚到上一个合法状态
    delete(c.Batches, batchID)
    return nil
}

// FinalizeBatch 挑战窗口过后最终确定批次
func (c *L1Contract) FinalizeBatch(batchID uint64) error {
    batch, ok := c.Batches[batchID]
    if !ok {
        return fmt.Errorf("批次 %d 不存在", batchID)
    }

    if time.Since(batch.SubmittedAt) < batch.ChallengeWindow {
        remaining := batch.ChallengeWindow - time.Since(batch.SubmittedAt)
        return fmt.Errorf("挑战窗口未关闭，还需等待 %s", remaining)
    }

    c.FinalizedBatches[batchID] = true
    fmt.Printf("[OR] ✓ 批次 %d 已最终确定（挑战窗口已过，不可逆）\n", batchID)
    return nil
}

// ─── 欺诈证明（Fraud Proof）───

// FraudProof 欺诈证明
// 核心：指出批次中第 N 笔交易执行后状态根不匹配
type FraudProof struct {
    BatchID       uint64
    DisputedTX    int     // 争议的交易索引
    PreStateRoot  [32]byte // 执行该交易前的状态根
    PostStateRoot [32]byte // 正确的执行后状态根（我算出来的）
    WrongStateRoot [32]byte // Sequencer 声称的状态根（错的）
    // 交互式欺诈证明需要更复杂的二分查找过程
}

// VerifyFraudProof 验证欺诈证明
// 对于交互式欺诈证明，L1 合约只验证单步执行
func (c *L1Contract) verifyFraudProof(batch *L2Batch, proof *FraudProof) bool {
    // 1. 验证 PreStateRoot 是否在该批次中被引用
    // 2. 在 L1 上重新执行该笔交易（单步）
    // 3. 比对结果

    // 简化：假设验证逻辑
    computedPostState := executeSingleTX(batch.Transactions[proof.DisputedTX], proof.PreStateRoot)

    if computedPostState == proof.PostStateRoot &&
        computedPostState != proof.WrongStateRoot {
        fmt.Printf("[OR] 欺诈证明核验通过: TX %d 执行后状态根 0x%x ≠ Sequencer声称的 0x%x\n",
            proof.DisputedTX,
            proof.PostStateRoot[:4],
            proof.WrongStateRoot[:4],
        )
        return true
    }

    return false
}

func executeSingleTX(txData string, preState [32]byte) [32]byte {
    // L1 合约执行单笔 EVM 交易的简化模拟
    h := sha256.New()
    h.Write(preState[:])
    h.Write([]byte(txData))
    var result [32]byte
    copy(result[:], h.Sum(nil))
    return result
}
```

#### Optimistic Rollup 的优缺点

| 优点 | 缺点 |
|------|------|
| 技术成熟（Arbitrum/Optimism 已大规模运行） | **提款需等 7 天**挑战期 |
| 开发者友好，完全 EVM 兼容 | 欺诈证明在 L1 上执行成本高 |
| L1 验证成本低（正常情况下） | 需要诚实观察者持续监控 |
| 无需复杂的 zk 密码学 | 极端情况下可能被成功欺诈 |

### 2.2 ZK Rollup（零知识汇总）

**核心思想**：每批交易生成零知识证明（有效性证明），L1 验证证明后立即最终确定，无需挑战期。

```
流程：

  Sequencer 打包交易
       ↓
  执行交易，计算状态根
       ↓
  Prover 生成 zk 证明（证明状态转换合法）
       ↓
  提交 calldata + zk proof 到 L1
       ↓
  L1 验证 zk proof
  ├─ 验证通过 → 立即 Finalized ✓
  └─ 验证失败 → 拒绝批次
```

#### Go 代码示例：ZK Rollup 核心逻辑

```go
package zkrollup

import (
    "crypto/rand"
    "crypto/sha256"
    "fmt"
    "math/big"
    "time"
)

// ─── ZK Rollup 核心组件 ───

// ZKBatch ZK 批次
type ZKBatch struct {
    BatchID       uint64
    Transactions  []string
    PrevStateRoot [32]byte
    NewStateRoot  [32]byte
    CalldataHash  [32]byte
    ZKProof       *ValidityProof // 有效性证明
}

// ValidityProof 有效性证明（简化版 zk-SNARK）
//
// 证明内容：
// "我知道一个状态转换，从 prevStateRoot 到 newStateRoot，
//  它正确地执行了批次中的所有交易（没有作弊）"
type ValidityProof struct {
    A [2]*big.Int // G1 点
    B [2][2]*big.Int // G2 点
    C [2]*big.Int // G1 点

    // 公开输入
    PublicInputs [][32]byte // prevStateRoot, newStateRoot, calldataHash
}

// ZKRollupContract L1 上的 ZK Rollup 合约
type ZKRollupContract struct {
    LastFinalizedRoot [32]byte
    Batches           map[uint64]*ZKBatch
    Provers           map[string]bool // 授权的 Prover
}

// SubmitBatchWithProof 提交批次 + zk 证明
func (c *ZKRollupContract) SubmitBatchWithProof(batch *ZKBatch) error {
    // 1. 验证 prevStateRoot 与当前 finalized root 一致
    if batch.PrevStateRoot != c.LastFinalizedRoot {
        return fmt.Errorf("prevStateRoot 不匹配当前链上状态")
    }

    // 2. 验证 zk proof
    if !c.verifyZKProof(batch.ZKProof) {
        return fmt.Errorf("zk 有效性证明验证失败")
    }

    // 3. 验证通过 → 立即最终确定！
    // 不需要挑战期
    c.LastFinalizedRoot = batch.NewStateRoot
    c.Batches[batch.BatchID] = batch

    fmt.Printf("[ZK] ✓ 批次 %d 已提交并立即 Finalized | 交易数: %d\n",
        batch.BatchID, len(batch.Transactions))
    fmt.Printf("[ZK]    状态根: 0x%x → 0x%x\n",
        batch.PrevStateRoot[:8], batch.NewStateRoot[:8])

    return nil
}

// VerifyZKProof L1 合约验证 zk 证明
// 这是 ZK Rollup 的精髓：几百字节的 proof，毫秒级验证
func (c *ZKRollupContract) verifyZKProof(proof *ValidityProof) bool {
    // 简化：真实场景使用 Groth16 或 PLONK 验证算法
    // 验证公式（Groth16 简化）：e(A,B) == e(C,g) * e(public_inputs)

    // 1. 检查公开输入
    if len(proof.PublicInputs) < 3 {
        return false
    }

    // 2. 执行椭圆曲线配对验证
    // e(proof.A, proof.B) == e(proof.C, G2) * e(pub_input_commitment, G2)
    //
    // 实际代码使用 bn254 或 BLS12-381 曲线：
    //   err := groth16.Verify(proof, vk, publicInputs)
    //   return err == nil

    valid := verifyPairing(proof)

    if valid {
        fmt.Println("[ZK] zk-SNARK 证明验证通过 ✓")
    }

    return valid
}

func verifyPairing(proof *ValidityProof) bool {
    // 简化：实际使用 gnark 或 gnark-crypto 的配对验证
    return true
}
```

### 2.3 Validium

**核心思想**：和 ZK Rollup 一样用 zk 证明，但交易数据不放在 L1，而是由 **DAC（数据可用性委员会）** 保管。

```
ZK Rollup vs Validium 的区别：

  ZK Rollup:
    L1 存储: calldata（数据可用性靠以太坊保证）
    成本: 仍有一定 Gas 开销（存储 calldata）

  Validium:
    L1 存储: 仅状态根 + zk proof
    原始数据: 链下 DAC 委员会保管
    成本: 极低（不需要在 L1 存 calldata）
```

#### Go 代码示例：Validium DAC 机制

```go
package validium

import (
    "crypto/sha256"
    "fmt"
)

// ─── Validium 数据可用性委员会（DAC）───

// DACMember DAC 委员会成员
type DACMember struct {
    ID        string
    PublicKey []byte
    Stake     uint64 // 质押金额
}

// DataAvailabilityCommittee 数据可用性委员会
type DataAvailabilityCommittee struct {
    Members       []*DACMember
    Threshold     int     // 最少需要多少成员签名（如 N/2 + 1）
}

// DataAvailabilityCertificate 数据可用性证书
// 由 DAC 委员会签名确认数据在链下可用
type DataAvailabilityCertificate struct {
    BatchID      uint64
    DataHash     [32]byte
    Signatures   [][]byte // 委员会成员的签名
    Timestamp    int64
}

// ValidiumContract L1 上的 Validium 合约
type ValidiumContract struct {
    DAC               *DataAvailabilityCommittee
    LastValidatedRoot [32]byte
    Batches           map[uint64]*ValidiumBatch
}

// ValidiumBatch Validium 批次
type ValidiumBatch struct {
    BatchID       uint64
    PrevStateRoot [32]byte
    NewStateRoot  [32]byte
    ZKProof       []byte // zk 有效性证明
    DACertificate *DataAvailabilityCertificate // DA 证书
}

// SubmitBatch 提交批次
func (c *ValidiumContract) SubmitBatch(batch *ValidiumBatch) error {
    // 1. 验证 zk proof（与 ZK Rollup 相同）
    if !c.verifyZKProof(batch.ZKProof) {
        return fmt.Errorf("zk 证明验证失败")
    }

    // 2. 验证 DA 证书
    // 需要足够多委员会成员签名
    if !c.verifyDACertificate(batch.DACertificate) {
        return fmt.Errorf("DA 证书验证失败：签名不足或数据不可用")
    }

    // 3. 立即最终确定
    c.LastValidatedRoot = batch.NewStateRoot
    c.Batches[batch.BatchID] = batch

    fmt.Printf("[Validium] ✓ 批次 %d 已 Finalized\n", batch.BatchID)
    fmt.Printf("[Validium]    zk proof 验证通过 + DA 证书有效\n")
    return nil
}

// VerifyDACertificate 验证数据可用性证书
func (c *ValidiumContract) verifyDACertificate(cert *DataAvailabilityCertificate) bool {
    if cert == nil {
        return false
    }

    validSignatures := 0
    for _, sig := range cert.Signatures {
        // 验证签名来自合法委员会成员
        if c.verifyDACSignature(cert.DataHash, sig) {
            validSignatures++
        }
    }

    required := c.DAC.Threshold
    valid := validSignatures >= required

    fmt.Printf("[Validium] DA 证书: %d/%d 签名（需要 %d）%s\n",
        validSignatures, len(c.DAC.Members), required,
        map[bool]string{true: "✓", false: "✗"}[valid])

    return valid
}

func (c *ValidiumContract) verifyDACSignature(dataHash [32]byte, sig []byte) bool {
    return len(sig) > 0
}

// ─── Validium 的退出场景 ───

// EmergencyWithdraw 紧急提款
// 如果 DAC 停止响应 → 用户数据锁死
// Validium 需要"逃生舱"机制：通过 L1 上的 merkle proof 提款
func (c *ValidiumContract) EmergencyWithdraw(
    user string,
    merkleProof *MerkleProof,
    balance uint64,
) error {
    // 1. 验证当前状态根中包含用户余额的 merkle proof
    if !verifyMerkleProof(c.LastValidatedRoot, merkleProof, user, balance) {
        return fmt.Errorf("merkle 证明验证失败")
    }

    // 2. 检查冻结期
    // 需要等待足够时间确认 DAC 确实不可用
    if !c.isDACUnavailable() {
        return fmt.Errorf("DAC 仍在工作，使用正常提款通道")
    }

    fmt.Printf("[Validium] 🆘 紧急提款: %s 提取 %d（DAC 不可用）\n",
        user[:16]+"...", balance)

    return nil
}
```

### 2.4 状态通道（State Channels）

**核心思想**：交易完全在链下进行，只在开关通道时与 L1 交互。适合高频小额支付。

```
流程：

  开通道:  双方在 L1 锁定资金 → 创建通道
  链下交易: 双方互相签名，更新通道余额（瞬间、零费用）
  关通道:  最终状态提交 L1 → 双方按最终余额分账
  争议:    一方作弊提交旧状态 → 另一方在挑战期内举报
```

#### Go 代码示例：状态通道

```go
package statechannel

import (
    "crypto/ecdsa"
    "crypto/elliptic"
    "crypto/rand"
    "crypto/sha256"
    "fmt"
    "math/big"
    "sync"
    "time"

// ─── 状态通道 ───

// ChannelState 通道状态
type ChannelState struct {
    ChannelID   [32]byte
    Participants [2]string
    BalanceA    uint64 // Alice 的余额
    BalanceB    uint64 // Bob 的余额
    Nonce       uint64 // 防重放：每笔交易递增
}

// SignedState 签名后的状态（链下交易的核心）
type SignedState struct {
    State     ChannelState
    SigA      []byte // Alice 签名
    SigB      []byte // Bob 签名
}

// OnChainChannel L1 上的通道合约
type OnChainChannel struct {
    ChannelID      [32]byte
    TotalDeposited uint64
    ParticipantA   string
    ParticipantB   string
    FinalizedState *ChannelState
    ChallengeUntil time.Time
    Closed         bool
    mu             sync.Mutex
}

// ─── 通道生命周期 ───

// OpenChannel 在 L1 上打开通道
func OpenChannel(
    participantA, participantB string,
    amountA, amountB uint64,
) (*OnChainChannel, *ChannelState, error) {

    channelID := generateChannelID(participantA, participantB)

    channel := &OnChainChannel{
        ChannelID:      channelID,
        TotalDeposited: amountA + amountB,
        ParticipantA:   participantA,
        ParticipantB:   participantB,
    }

    // 初始状态
    state := &ChannelState{
        ChannelID:    channelID,
        Participants: [2]string{participantA, participantB},
        BalanceA:     amountA,
        BalanceB:     amountB,
        Nonce:        0,
    }

    fmt.Printf("[通道] 🔓 通道已开启 | ID: 0x%x\n", channelID[:8])
    fmt.Printf("[通道]    Alice: %d | Bob: %d | 总锁定: %d\n",
        amountA, amountB, amountA+amountB)

    return channel, state, nil
}

// OffChainTransfer 链下转账（核心：双方签名新状态）
func OffChainTransfer(
    currentState *SignedState,
    from string, // "A" 或 "B"
    amount uint64,
    privKeyA, privKeyB *ecdsa.PrivateKey,
) (*SignedState, error) {

    // 1. 复制当前状态
    newState := currentState.State
    newState.Nonce++

    // 2. 更新余额
    if from == "A" {
        if newState.BalanceA < amount {
            return nil, fmt.Errorf("Alice 余额不足")
        }
        newState.BalanceA -= amount
        newState.BalanceB += amount
    } else {
        if newState.BalanceB < amount {
            return nil, fmt.Errorf("Bob 余额不足")
        }
        newState.BalanceB -= amount
        newState.BalanceA += amount
    }

    // 3. 双方签名
    stateBytes := serializeState(newState)
    sigA, _ := signData(stateBytes, privKeyA)
    sigB, _ := signData(stateBytes, privKeyB)

    signed := &SignedState{
        State: newState,
        SigA:  sigA,
        SigB:  sigB,
    }

    fmt.Printf("[链下] ⚡ TX #%d: %s → 对方 %d | 余额 A:%d B:%d | 零Gas\n",
        newState.Nonce, from, amount, newState.BalanceA, newState.BalanceB)

    return signed, nil
}

// CloseChannelCooperatively 双方协作关闭通道（最快）
func CloseChannelCooperatively(
    channel *OnChainChannel,
    finalState *SignedState,
) error {
    channel.mu.Lock()
    defer channel.mu.Unlock()

    // 双方都签名 → 立即结算，无需等待
    channel.FinalizedState = &finalState.State
    channel.Closed = true

    fmt.Printf("[通道] 🔒 协作关闭 | Alice: %d | Bob: %d\n",
        finalState.State.BalanceA, finalState.State.BalanceB)

    // L1 释放资金
    // transfer(channel.ParticipantA, finalState.BalanceA)
    // transfer(channel.ParticipantB, finalState.BalanceB)

    return nil
}

// CloseChannelUnilaterally 单方面关闭通道（一方想关）
func CloseChannelUnilaterally(
    channel *OnChainChannel,
    closingState *SignedState,
) error {
    channel.mu.Lock()
    defer channel.mu.Unlock()

    // 只有一方签名 → 进入挑战期
    channel.FinalizedState = &closingState.State
    channel.ChallengeUntil = time.Now().Add(7 * 24 * time.Hour) // 7天挑战期

    fmt.Printf("[通道] ⏳ 单方关闭 | 进入 7 天挑战期\n")

    return nil
}

// ChallengeClose 挑战对方提交的旧状态
//
// 如果对方提交了过期的旧状态（比如 Nonce 低的版本），
// 另一方可以在挑战期内提交更新的状态来纠正
func ChallengeClose(
    channel *OnChainChannel,
    newerState *SignedState,
) error {
    channel.mu.Lock()
    defer channel.mu.Unlock()

    if time.Now().After(channel.ChallengeUntil) {
        return fmt.Errorf("挑战期已过")
    }

    // 检查是否真的是更新状态
    if newerState.State.Nonce <= channel.FinalizedState.Nonce {
        return fmt.Errorf("提交的状态不更新")
    }

    // 更新为更新状态
    channel.FinalizedState = &newerState.State
    fmt.Printf("[通道] ⚠️ 挑战成功！状态已更新为 Nonce=%d\n", newerState.State.Nonce)

    // 惩罚作弊方（没收其通道资金）

    return nil
}

func generateChannelID(a, b string) [32]byte {
    h := sha256.New()
    h.Write([]byte(a))
    h.Write([]byte(b))
    var id [32]byte
    copy(id[:], h.Sum(nil))
    return id
}

func serializeState(s ChannelState) []byte {
    return []byte(fmt.Sprintf("%x:%d:%d:%d", s.ChannelID, s.BalanceA, s.BalanceB, s.Nonce))
}

func signData(data []byte, key *ecdsa.PrivateKey) ([]byte, error) {
    hash := sha256.Sum256(data)
    return ecdsa.SignASN1(rand.Reader, key, hash[:])
}
```

### 4.2 Go 代码：交易所 L2 接入评估器

```go
package exchange

import (
    "fmt"
    "time"
)

// L2Assessment 交易所 L2 接入评估
type L2Assessment struct {
    Name              string
    Type              string // "zk_rollup" | "optimistic" | "validium"
    WithdrawalTime    time.Duration
    EVMCompatible     bool
    MainnetLive       bool
    SequencerDecentralized bool
    Score             float64 // 综合评分
}

func AssessL2ForExchange() {
    l2s := []L2Assessment{
        {"Arbitrum One", "optimistic", 7 * 24 * time.Hour, true, true, false, 0},
        {"Optimism", "optimistic", 7 * 24 * time.Hour, true, true, false, 0},
        {"zkSync Era", "zk_rollup", 5 * time.Minute, true, true, false, 0},
        {"StarkNet", "zk_rollup", 10 * time.Minute, false, true, false, 0},
        {"Scroll", "zk_rollup", 20 * time.Minute, true, true, false, 0},
        {"Base", "optimistic", 7 * 24 * time.Hour, true, true, false, 0},
        {"Linea", "zk_rollup", 15 * time.Minute, true, true, false, 0},
        {"Immutable X", "validium", 1 * time.Minute, false, true, false, 0},
    }

    // 评分逻辑
    for i := range l2s {
        score := 0.0

        // 提款速度权重: 40%
        switch {
        case l2s[i].WithdrawalTime <= 5*time.Minute:
            score += 40
        case l2s[i].WithdrawalTime <= 30*time.Minute:
            score += 30
        case l2s[i].WithdrawalTime <= 24*time.Hour:
            score += 10
        default:
            score += 0 // 7天 = 0分（对交易所不可接受）
        }

        // 安全性权重: 30%
        switch l2s[i].Type {
        case "zk_rollup":
            score += 30 // zk 证明即最终确定
        case "optimistic":
            score += 20 // 需要诚实观察者
        case "validium":
            score += 15 // 依赖 DAC
        }

        // EVM 兼容权重: 20%
        if l2s[i].EVMCompatible {
            score += 20
        }

        // 去中心化权重: 10%
        if l2s[i].SequencerDecentralized {
            score += 10
        }

        l2s[i].Score = score
    }

    // 输出排名
    fmt.Println("╔══════════════════╦══════════╦══════════╦══════════╦══════╗")
    fmt.Println("║  L2               ║ 类型      ║ 提款时间   ║ EVM兼容  ║ 评分  ║")
    fmt.Println("╠══════════════════╬══════════╬══════════╬══════════╬══════╣")
    for _, l2 := range l2s {
        fmt.Printf("║ %-17s ║ %-8s ║ %-8s ║ %-8v ║ %4.0f ║\n",
            l2.Name, l2.Type, formatDurationShort(l2.WithdrawalTime),
            l2.EVMCompatible, l2.Score)
    }
    fmt.Println("╚══════════════════╩══════════╩══════════╩══════════╩══════╝")
    fmt.Println()
    fmt.Println("推荐：优先接入 ZK Rollup 类 L2（zkSync Era、Scroll、Linea）")
    fmt.Println("      Optimistic Rollup 通过第三方快速桥可部分解决 7 天问题")
    fmt.Println("      但快速桥引入了额外信任假设，需风控评估")
}

func formatDurationShort(d time.Duration) string {
    if d < time.Hour {
        return fmt.Sprintf("%.0f分钟", d.Minutes())
    }
    if d < 24*time.Hour {
        return fmt.Sprintf("%.0f小时", d.Hours())
    }
    return fmt.Sprintf("%.0f天", d.Hours()/24)
}
```

## 五、L2 风险清单（交易所视角）

| 风险类型 | 描述 | 缓解措施 |
|---------|------|---------|
| **Sequencer 单点故障** | 大部分 L2 sequencer 仍为中心化 | 监控 L1 强制提款通道，接入 fallback |
| **欺诈证明无效** | OR 的欺诈证明可能在极端 Gas 下无法提交 | 多节点独立监控，预留高 Gas 预算 |
| **升级密钥风险** | L2 合约可升级，有多签控制风险 | 监控升级事件，设置提款延迟 |
| **跨链桥攻击** | L1↔L2 桥被黑（历史上最大的漏洞点） | 限制单次提款金额，保险基金 |
| **数据不可用** | Validium 的 DAC 可能串谋扣留数据 | 仅用 ZK Rollup，不依赖链下 DA |
| **Prover 故障** | ZK Rollup 的 prover 故障 → 批次延迟 | 备选 prover 集群 |
