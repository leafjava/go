# 隐私链（Privacy Chain）详解

## 一、什么是隐私链

传统区块链（如 Bitcoin、Ethereum）的最大特点是**链上数据公开透明**——任何人都可以查看任意地址的余额和交易历史。这在金融场景中会引发严重问题：大户的仓位、交易策略完全暴露在链上，成为 MEV 攻击和跟单狙击的目标。

隐私链的核心目标是：**让链上交易数据对第三方不可见，同时保留可验证性**。也就是说：
- 交易金额、发送方、接收方对外部观察者隐藏
- 但共识节点仍能验证交易合法性（没有双花、余额充足等）
- 理想情况下，监管方可在授权后审计

## 二、三大技术路线

### 2.1 零知识证明路线（zk-SNARKs / zk-STARKs）

**核心思想**：向验证者证明"我知道一个秘密，它能满足某些条件"，但不透露秘密本身。

#### 技术原理

zk-SNARK 的完整流程：

1. **电路化**：将验证逻辑编译为算术电路
2. **可信设置**：生成证明密钥（pk）和验证密钥（vk）
3. **生成证明**：Prover 用私密输入 + pk 生成 proof
4. **验证证明**：Verifier 用公开输入 + proof + vk 验证

```
┌──────────┐     证明 π       ┌──────────┐
│  Prover  │ ──────────────→ │ Verifier  │
│  (用户)  │                  │  (节点)   │
│          │                  │           │
│ 秘密输入: │                  │ 公开输入:  │
│  - sk    │                  │  - nullifier
│  - 金额  │                  │  - merkle root
│  - 路径  │                  │           │
└──────────┘                  └──────────┘
```

#### Go 代码示例：使用 gnark 库实现简单混币器

```go
package main

import (
    "crypto/rand"
    "fmt"
    "math/big"

    "github.com/consensys/gnark-crypto/ecc"
    "github.com/consensys/gnark/backend/groth16"
    "github.com/consensys/gnark/frontend"
    "github.com/consensys/gnark/frontend/cs/r1cs"
)

// MixerCircuit 混币器电路：证明我知道 preimage，它的哈希存在于 Merkle Tree 中
type MixerCircuit struct {
    // 公开输入
    MerkleRoot frontend.Variable `gnark:",public"`  // Merkle 树根
    Nullifier  frontend.Variable `gnark:",public"`  // 防止双花的唯一标识

    // 私密输入
    Preimage frontend.Variable   // 原始秘密
    Path     [32]frontend.Variable // Merkle 证明路径
    Helper   [32]frontend.Variable // 路径方向（左/右）
}

func (circuit *MixerCircuit) Define(api frontend.API) error {
    // 1. 计算 nullifier = hash(preimage)，确保与公开输入一致
    computedNullifier := api.Hash(circuit.Preimage)
    api.AssertIsEqual(computedNullifier, circuit.Nullifier)

    // 2. 计算 commitment = hash(nullifier)，这是存在 Merkle Tree 中的值
    commitment := api.Hash(circuit.Nullifier)

    // 3. 验证 Merkle 证明：从 commitment 出发，一步步算到 root
    currentHash := commitment
    for i := 0; i < len(circuit.Path); i++ {
        // 根据 direction 选择左右拼接顺序
        leftInput := api.Select(circuit.Helper[i], currentHash, circuit.Path[i])
        rightInput := api.Select(circuit.Helper[i], circuit.Path[i], currentHash)
        currentHash = api.Hash(leftInput, rightInput)
    }

    // 4. 断言计算出的 root 等于公开的 root
    api.AssertIsEqual(currentHash, circuit.MerkleRoot)

    return nil
}

// GeneratePedersenCommitment 生成 Pedersen 承诺

func GeneratePedersenCommitment(amount *big.Int, blinding *big.Int) (commitment string) {
    // G 和 H 是椭圆曲线上的生成元，且它们之间的离散对数关系未知
    // Cx = amount * Gx + blinding * Hx
    // Cy = amount * Gy + blinding * Hy
    // 实际实现需要用到椭圆曲线群运算
    fmt.Printf("C = %d·G + %d·H\n", amount, blinding)
    return "commitment_value"
}

// VerifyRangeProof 验证范围证明（Bulletproofs 简化示意）
// 证明 amount 在 [0, 2^n) 范围内，但不透露具体值
func VerifyRangeProof(commitment string, proof []byte, n int) bool {
    // Bulletproofs 的核心：将 amount 二进制分解
    // amount = a0 + a1*2 + a2*4 + ... + a_{n-1}*2^{n-1}
    // 对每一位 ai 证明 ai*(1-ai) = 0（即 ai ∈ {0,1}）
    // 然后用内积证明将所有位证明压缩成一个
    fmt.Printf("验证 %s 对应的金额在 [0, 2^%d) 范围内\n", commitment, n)
    return true
}
```

#### zk-SNARK 透明化关键步骤示意

```
存款阶段：
  用户 ──存入 1 ETH──→ 合约
  合约存储: commitment = hash(nullifier)
  合约插入 Merkle Tree

取款阶段：
  用户生成 zk 证明:
    输入（私密）: nullifier, merkle_path
    输出（公开）: nullifier_hash, merkle_root, 接收地址
  合约验证:
    1. nullifier 是否已花过？
    2. merkle_root 是否在当前树中？
    3. zk 证明是否有效？
  通过 → 释放资金到接收地址，标记 nullifier 已使用
```

#### zk-SNARK vs zk-STARK 对比

| 特性 | zk-SNARK | zk-STARK |
|------|----------|----------|
| 证明大小 | 小（~200 bytes） | 大（~50 KB） |
| 验证时间 | 快 | 略慢 |
| 可信设置 | **需要** | **不需要** |
| 抗量子 | 否 | 是 |
| 代表项目 | Zcash, Tornado Cash | StarkNet, StarkWare |

### 2.2 TEE 可信执行环境路线

**核心思想**：代码和数据在 CPU 级别的安全飞地（Enclave）中运行，宿主机操作系统和物理持有者都无法窥探。

#### 技术原理

```
┌──────────────────────────────────┐
│           普通执行环境            │
│  ┌────────────────────────────┐  │
│  │    TEE 安全飞地 (Enclave)   │  │
│  │                            │  │
│  │  ┌──────────┐ ┌─────────┐  │  │
│  │  │ 合约代码  │ │ 合约状态 │  │  │
│  │  │ (明文)   │ │ (明文)  │  │  │
│  │  └──────────┘ └─────────┘  │  │
│  │                            │  │
│  │  加密内存页，硬件隔离       │  │
│  └────────────────────────────┘  │
│         ↑ 无法访问               │
│   宿主 OS / 物理管理员           │
└──────────────────────────────────┘
```

### 2.3 环签名 + 隐身地址路线

**核心思想**：把发送者混进一群人里（环签名），用一次性地址隐藏接收者（隐身地址）。

#### 技术原理

```
环签名：
┌──────────────────────────────────────┐
│  签名者：Alice（实际的发送方）           │
│  环成员：{Alice, Bob, Carol, Dave}     │
│  观察者只知道：签名来自这4人之一         │
│  但无法确定具体是谁                     │
│                                      │
│  KeyImage：防止同一密钥签名两次          │
└──────────────────────────────────────┘

隐身地址：
  发送者 → 用接收者的公钥 + 随机数 → 生成一次性地址
  接收者 → 扫描链上所有交易 → 用自己的私钥尝试解密 → 找到发给自己的交易
```

#### Go 代码示例：简化版环签名实现

```go
package main

import (
    "crypto/ecdsa"
    "crypto/elliptic"
    "crypto/rand"
    "crypto/sha256"
    "fmt"
    "math/big"
)

// ─── 简化版环签名 ───
// 注：这是教育目的的简化实现，实际应使用 LSAG/CLSAG 算法

// RingSignature 环签名结构
type RingSignature struct {
    C0       *big.Int     // 初始挑战值
    S        []*big.Int   // 各环成员的响应值
    KeyImage *big.Int     // 防止双花的密钥镜像
}

// RingMember 环成员
type RingMember struct {
    PublicKey *ecdsa.PublicKey
}

// SignAsRingMember 环签名生成
// signerIndex: 实际签名者在环中的索引（不公开）
// message: 要签名的消息
// privateKey: 签名者的私钥
// ring: 环成员的公钥列表
//
// 关键性质：验证者能确认"签名来自环中某人"，
// 但无法确定具体是谁（除非环大小为1）
func SignAsRingMember(
    signerIndex int,
    message []byte,
    privateKey *ecdsa.PrivateKey,
    ring []RingMember,
) (*RingSignature, error) {

    ringSize := len(ring)
    if ringSize < 2 {
        return nil, fmt.Errorf("环至少需要2个成员")
    }

    // 1. 生成随机数
    q := make([]*big.Int, ringSize)
    commitments := make([]*ecdsa.PublicKey, ringSize)

    // 2. 为所有非签名者生成随机承诺
    for i := 0; i < ringSize; i++ {
        if i == signerIndex {
            continue
        }
        q[i], _ = rand.Int(rand.Reader, elliptic.P256().Params().N)
        // commitment = q[i] * G
        x, y := elliptic.P256().ScalarBaseMult(q[i].Bytes())
        commitments[i] = &ecdsa.PublicKey{Curve: elliptic.P256(), X: x, Y: y}
    }

    // 3. 为签名者生成随机数 k
    k, _ := rand.Int(rand.Reader, elliptic.P256().Params().N)
    kx, ky := elliptic.P256().ScalarBaseMult(k.Bytes())
    signerCommitment := &ecdsa.PublicKey{Curve: elliptic.P256(), X: kx, Y: ky}

    // 4. 计算挑战值（LSAG 风格）
    challenge := computeRingChallenge(message, commitments, signerCommitment, signerIndex)
    s := make([]*big.Int, ringSize)

    // 5. 签名者用自己的私钥响应挑战
    s[signerIndex] = new(big.Int).Mul(challenge, privateKey.D)
    s[signerIndex] = s[signerIndex].Add(s[signerIndex], k)
    s[signerIndex] = s[signerIndex].Mod(s[signerIndex], elliptic.P256().Params().N)

    // 6. 计算 KeyImage = sk * H_p(P)（防止双花的关键）
    keyImage := computeKeyImage(privateKey)

    return &RingSignature{
        C0:       challenge,
        S:        s,
        KeyImage: keyImage,
    }, nil
}

// VerifyRingSignature 验证环签名
// 验证者可以确认签名来自环中某个成员，但不知道具体是谁
func VerifyRingSignature(
    message []byte,
    sig *RingSignature,
    ring []RingMember,
) bool {
    // 1. 检查 KeyImage 是否已使用（防双花）
    if isKeyImageUsed(sig.KeyImage) {
        fmt.Println("✗ KeyImage 已被使用 → 双花攻击！")
        return false
    }

    // 2. 验算环签名方程
    // 对于 LSAG，验证 Σ s_i * G = c_0 * P_π + ... (简化)
    commitmentSumX, commitmentSumY := new(big.Int), new(big.Int)

    for i, member := range ring {
        siGx, siGy := elliptic.P256().ScalarBaseMult(sig.S[i].Bytes())
        ciPx, ciPy := elliptic.P256().ScalarMult(
            member.PublicKey.X, member.PublicKey.Y, sig.C0.Bytes(),
        )
        sumX, sumY := elliptic.P256().Add(siGx, siGy, ciPx, ciPy)
        commitmentSumX, commitmentSumY = sumX, sumY
    }

    _ = commitmentSumX
    _ = commitmentSumY

    // 3. 标记 KeyImage 已使用
    markKeyImageUsed(sig.KeyImage)

    fmt.Println("✓ 环签名验证通过：发送者是环中某人（不可追踪）")
    return true
}

// ─── 隐身地址（Stealth Address）───

// StealthAddress 隐身地址系统
type StealthAddress struct {
    ScanPubKey  *ecdsa.PublicKey  // 扫描公钥
    SpendPubKey *ecdsa.PublicKey  // 花费公钥
}

// GenerateStealthAddress 发送方生成一次性隐身地址
//
// 流程：
// 1. 发送方获取接收方的 (ScanPubKey, SpendPubKey)
// 2. 发送方生成随机数 r
// 3. 计算 R = r * G（发布到链上）
// 4. 计算共享秘密 s = r * ScanPubKey
// 5. 一次性公钥 P = s * G + SpendPubKey
// 6. 资金发送到 P
//
// 接收方扫描恢复：
// 1. 遍历链上所有 R
// 2. 计算 s' = scanPrivKey * R
// 3. 计算 P' = s' * G + SpendPubKey
// 4. 检查 P' 对应的地址是否有资金
func GenerateStealthAddress(
    scanPubKey *ecdsa.PublicKey,
    spendPubKey *ecdsa.PublicKey,
) (stealthPubKey *ecdsa.PublicKey, R *ecdsa.PublicKey, err error) {

    // 1. 生成随机数 r
    r, err := rand.Int(rand.Reader, elliptic.P256().Params().N)
    if err != nil {
        return nil, nil, err
    }

    // 2. 计算 R = r * G（公开在链上）
    rX, rY := elliptic.P256().ScalarBaseMult(r.Bytes())
    R = &ecdsa.PublicKey{Curve: elliptic.P256(), X: rX, Y: rY}

    // 3. 计算共享秘密 s = r * ScanPubKey
    sX, sY := elliptic.P256().ScalarMult(scanPubKey.X, scanPubKey.Y, r.Bytes())

    // 4. 一次性公钥 P = hash(s) * G + SpendPubKey
    sHash := sha256.Sum256(append(sX.Bytes(), sY.Bytes()...))
    hsX, hsY := elliptic.P256().ScalarBaseMult(sHash[:])
    px, py := elliptic.P256().Add(hsX, hsY, spendPubKey.X, spendPubKey.Y)

    stealthPubKey = &ecdsa.PublicKey{Curve: elliptic.P256(), X: px, Y: py}

    fmt.Printf("一次性隐身地址: 0x%x...\n", px.Bytes()[:8])
    return stealthPubKey, R, nil
}

// ScanForIncomingFunds 接收方扫描链上交易，找到发给自己的资金
func ScanForIncomingFunds(
    scanPrivKey *ecdsa.PrivateKey,
    spendPrivKey *ecdsa.PrivateKey,
    allTransactions []TransactionOnChain,
) []FoundTransaction {
    var found []FoundTransaction

    for _, tx := range allTransactions {
        // 1. 提取 R
        R := tx.R

        // 2. 计算共享秘密 s' = scanPrivKey * R
        sX, sY := elliptic.P256().ScalarMult(R.X, R.Y, scanPrivKey.D.Bytes())

        // 3. 计算 P' = hash(s') * G + SpendPubKey
        sHash := sha256.Sum256(append(sX.Bytes(), sY.Bytes()...))
        hsX, hsY := elliptic.P256().ScalarBaseMult(sHash[:])
        spendPubX, spendPubY := elliptic.P256().ScalarBaseMult(spendPrivKey.D.Bytes())
        expectedPX, expectedPY := elliptic.P256().Add(hsX, hsY, spendPubX, spendPubY)

        // 4. 检查是否匹配
        if expectedPX.Cmp(tx.Destination.X) == 0 && expectedPY.Cmp(tx.Destination.Y) == 0 {
            // 5. 对应的花费私钥 = s' + spendPrivKey
            spendKey := new(big.Int).Add(new(big.Int).SetBytes(sHash[:]), spendPrivKey.D)
            found = append(found, FoundTransaction{
                TX:         tx,
                SpendKey:   spendKey,
                Amount:     tx.Amount,
            })
        }
    }

    return found
}

func computeRingChallenge(msg []byte, commitments []*ecdsa.PublicKey, signerCommit *ecdsa.PublicKey, idx int) *big.Int {
    h := sha256.New()
    h.Write(msg)
    for _, c := range commitments {
        if c != nil {
            h.Write(c.X.Bytes())
            h.Write(c.Y.Bytes())
        }
    }
    h.Write(signerCommit.X.Bytes())
    h.Write(signerCommit.Y.Bytes())
    return new(big.Int).SetBytes(h.Sum(nil))
}

func computeKeyImage(priv *ecdsa.PrivateKey) *big.Int {
    // KeyImage = sk * H_p(P)，其中 H_p 是哈希到曲线函数
    pubKeyHash := sha256.Sum256(append(priv.PublicKey.X.Bytes(), priv.PublicKey.Y.Bytes()...))
    // 简化：用私钥乘以哈希值
    ki := new(big.Int).Mul(priv.D, new(big.Int).SetBytes(pubKeyHash[:]))
    return ki.Mod(ki, elliptic.P256().Params().N)
}

}
```

## 三、合规隐私（Compliance Privacy）—— 交易所视角

### 3.1 为什么纯隐私方案不够

纯隐私方案（如 Tornado Cash）让交易完全不可追踪，但这会引入严重问题：

- **无法满足 KYC/AML 要求**：监管机构要求交易所能追溯可疑交易
- **制裁风险**：像 Tornado Cash 已经被 OFAC 制裁
- **无法证明合规性**：交易所无法自证没有参与洗钱

### 3.2 合规隐私的架构

```
              ┌─────── 用户侧 ───────┐
              │                      │
              │  零知识证明生成       │
              │  ├─ 我 KYC 过了       │
              │  ├─ 我没洗钱         │
              │  ├─ 我没超限额       │
              │  └─ 交易金额（隐藏）  │
              │                      │
              └────────┬─────────────┘
                       │ zk proof
                       ↓
              ┌─────── 交易所侧 ───────┐
              │                        │
              │  zk proof 验证通过     │
              │  → 执行交易            │
              │  → 存储加密交易记录     │
              │                        │
              └────────┬───────────────┘
                       │
              ┌────────↓───────┐
              │  监管审计层    │
              │                │
              │  View Key 持有 │
              │  法院批准解密   │
              │  特定交易       │
              └────────────────┘
```

```go
// "我的交易是合规的"，但不暴露具体金额和对手方
func (p *PrivacyLayer) GenerateComplianceZKProof(
    kycCredential []byte,
    sanctionProof []byte,
    amount *big.Int,
    dailyLimit *big.Int,
    sourceFunds []string,
) ([]byte, error) {

    // 1. 检查 KYC 凭证有效性
    if !verifyKYCCredential(kycCredential) {
        return nil, fmt.Errorf("KYC 凭证无效")
    }

    // 2. 检查不在制裁名单中
    if !checkSanctionList(sanctionProof) {
        return nil, fmt.Errorf("地址在制裁名单中")
    }

    // 3. 检查金额不超限额（使用范围证明）
    if !isWithinRange(amount, big.NewInt(0), dailyLimit) {
        return nil, fmt.Errorf("交易金额超出日限额")
    }

    // 4. 生成合规证明
    // 对外只暴露 nullifier 和 merkle root
    // 不暴露金额、地址等隐私信息
    proof := ComplianceProof{
        KYCVerified:         true,
        NotSanctioned:       true,
        WithinLimit:         true,
        SufficientFunds:     true,
        SourceOfFundsValid:  true, // 简化：实际应验证资金来源
    }

    proofBytes, _ := json.Marshal(proof)
    hash := sha256.Sum256(proofBytes)

    fmt.Println("✓ 合规 zk 证明已生成（不暴露具体金额/地址）")
    return hash[:], nil
}

// AuditTransaction 监管审计：需法院批准才能解密特定交易
func (r *RegulatoryAuditor) AuditTransaction(
    txID string,
    courtOrder CourtOrder,
) (*TransactionDetail, error) {

    // 1. 验证法院令有效性
    if !r.verifyCourtOrder(courtOrder) {
        return nil, fmt.Errorf("无效的法院令")
    }

    // 2. 验证法院令未过期
    if time.Now().After(courtOrder.ExpiryDate) {
        return nil, fmt.Errorf("法院令已过期")
    }

    // 3. 验证法院令针对的交易 ID 匹配
    if courtOrder.TXID != txID {
        return nil, fmt.Errorf("法院令与审计交易不匹配")
    }

    // 4. 获取多方签名（至少 3 个独立方）
    // 例如：合规官、法务、CEO 各持一份密钥分片
    shards := r.collectKeyShards()
    if len(shards) < 3 {
        return nil, fmt.Errorf("密钥分片不足，需要至少3方签名")
    }

    // 5. 重组审计密钥
    fullAuditKey := recoverAuditKey(shards)

    // 6. 解密交易详情
    txDetail, err := r.decryptTransaction(txID, fullAuditKey)
    if err != nil {
        return nil, err
    }

    // 7. 记录审计日志（不可篡改）
    r.logAuditEvent(txID, courtOrder, time.Now())

    fmt.Println("✓ 监管审计完成：已解密特定交易")
    fmt.Printf("  审计日志: 法院令 %s, 审计时间: %s\n", courtOrder.CaseID, time.Now().Format(time.RFC3339))

    return txDetail, nil
}

            key[i] ^= s[i]

    return key
```

## 六、交易所选型建议

对于持牌交易所（如 HashKey），隐私链选型的关键考量：

1. **合规优先**：方案必须支持可审计性，纯匿名方案不可用
2. **选择性披露**：用户可证明合规性而不暴露交易细节
3. **监管友好**：支持 view key 机制，法院批准后可审计
4. **性能可行**：证明生成/验证速度能满足交易所吞吐量
5. **法律风险**：避免使用已被制裁的隐私协议（如 Tornado Cash）

**推荐方向**：合规隐私 L2（如 Aztec 的方向）+ 自定义合规预言机 + 监管审计层三层架构。
