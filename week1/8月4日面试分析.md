# 8月4日面试分析 — HashKey Spark 技术面 vs 全栈面试题对比

> **背景**：之前按 `hashkey-fullstack-interview-questions.md`（全栈/Web3 方向）准备了面试，这次实际面的岗位是 HashKey 内部 AI 平台（Spark）全栈/AI 开发岗（面试官李华），已按新岗位生成了 `hashkey-fullstack-spark.md`。
> **本文目的**：把两份面试题逐条对比，说清楚"哪些不用背、哪些换皮复用、哪些是全新的"，避免重复劳动。

---

## 一、结论先行（30 秒版）

- **不是推倒重来**：约 1/4 的题可以复用（React 基础、STAR 讲项目、交易所流程），约 3/4 是新内容或换皮。
- **主线彻底切换**：之前靠"Web3 合约技术"加分，这次靠"**AI 应用落地 + 业务对接**"加分。
- **你真正的王牌变了**：之前是 go-ethereum/多链，这次是 **Agent BL 项目 + 防欺骗 Skill**。
- **必考四道**：审核 Bot 架构、防注入、Agent BL、需求对接（几乎必问）。

## 四、全新的内容（之前完全没有，这次占 60% 以上权重）

这是两份文件**真正的分水岭**，Spark 面会大量问 LLM 工程和业务对接：

### 4.1 AI 平台 / LLM 应用（Q1-Q6）
- 内部 AI 平台核心功能模块设计（三层：能力/应用/治理）
- 企业级 AI Bot 完整架构（审核助手场景）
- 大模型落地四维：幻觉/成本/安全/权限
- RAG 知识库设计（分块/混合检索/重排/拒答）
- **防 Prompt 注入 / 简历藏字**（你的差异化优势）
- AI Bot 效果评估闭环（golden set + 人工反馈回流）

### 4.2 Agent 项目深度（Q7-Q9）
- Agent BL 用 STAR 讲透 + 4 条追问防御预案
- 多 Agent / 工作流设计（独立降级 / 状态机 / human-in-the-loop）
- 工具调用 Function Calling + 结构化输出

### 4.3 需求对接 & 业务理解（Q10-Q12，岗位核心软技能）
- 业务需求转 AI 方案四步法
- **给 HR/审核/开户团队做 AI Bot 怎么设计**（直接对应他们现在的工作）
- 跟非技术部门沟通需求、管理不现实预期

## 六、准备策略（换皮+新学，两线并行）

1. **主线彻底切换**：之前靠 Web3 合约题加分，这次全靠"AI 应用 + 业务结合"加分
2. **React/Go 基础留后备**：不用再背 Gin 中间件、GORM 锁这些细节，但"状态管理四层""SSE 流式"要熟
3. **四个必考答案背熟**：Q2 审核 Bot 架构、Q5 防注入四层、Q7 Agent BL STAR、Q10/Q11 需求对接
4. **所有技术答案都落到业务**：他们反复强调沟通能力，答完技术要补一句"这对业务意味着什么"
5. **把防欺骗 Skill 包装成合规差异化优势**：这是你和其他候选人最大的区分点
